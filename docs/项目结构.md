# 项目结构

当前项目分为数据转换、节理面识别和文档三层。原始资料与生成结果不放进算法源码目录。

```text

│   ├── app/main.py                   # main.py 的分发实现

│   │   ├── __init__.py               # 配置加载、合并、ROI 解析
│   │   ├── default.yaml
│   │   └── roi_example.yaml
│   ├── core/                         # 领域模型和几何基础
│   │   ├── models.py
│   │   ├── geometry.py
│   │   └── fitting.py                 # TLS/RANSAC 平面拟合
│   ├── processing/                   # 算法处理链
│   │   ├── preprocess.py             # 体素、离群点、局部特征
│   │   ├── segment.py                # 方向与空间分割
│   │   ├── density.py                 # 切平面 kNN 密度与 P10/P20/P21
│   │   ├── audit.py                   # V2 数据审计与源文件快照
│   │   ├── detachment.py              # 候选节理面几何质量筛选（历史模块名）
│   │   ├── spacing.py                 # 节理组和间距

│   │   ├── roi_compare.py             # 三 ROI 多尺度/层次合并消融实验
│   │   ├── whole_cloud_reporting.py   # 全点云报告与候选覆盖层映射准备

│   │   └── records.py                 # 类型结果到稳定输出记录的准备
│   ├── io/                           # 点云输入与结果写出
│   │   ├── las.py                     # LAS/LAZ 分块读取
│   │   ├── las_tiles.py                # LAS/COPC 瓦片读写原语
```

## 入口兼容性

日常运行统一使用项目根目录的 `main.py`，它只处理已有 LAS/LAZ，不调用
`osgb_pipeline`：

```bash
python3 main.py --plan-only
python3 main.py whole-cloud --input outputs/root_full_xyz_10/cloud.las \
  --output outputs/whole_cloud_joint_planes --tile-size 25 --overlap 1
python3 main.py roi --input outputs/root_full_xyz_10/cloud.las \
  --bbox 524898,524938,3132085,3132125 \
  --output outputs/discontinuity_roi_600
python3 main.py validate outputs/discontinuity_roi_600
```

为避免已有命令失效，以下文件保留兼容入口：

- `rock_discontinuity/whole_cloud.py` → `processing/whole_cloud.py`
- `rock_discontinuity/validate.py` → `validation/validate.py`
- `python3 -m rock_discontinuity` 保留历史 ROI 默认行为
- 根 `main.py` 与安装后的 `rock-discontinuity` 默认执行 whole-cloud

因此原有命令仍然有效：

```bash
python3 main.py whole-cloud --plan-only
PYTHONPATH=. python3 -m rock_discontinuity.validate outputs/discontinuity_roi_600
```

项目使用系统 Python，不要求创建或激活虚拟环境。依赖安装到当前用户目录：

```bash
python3 -m pip install --user 'setuptools>=68,<80' 'wheel>=0.40'
python3 -m pip install --user --no-build-isolation -c constraints.txt -e '.[osgb]'
# 运行测试时再安装开发依赖
python3 -m pip install --user --no-build-isolation -c constraints.txt -e '.[osgb,dev]'
```

`rock_discontinuity/requirements.txt` 和 `osgb_pipeline/requirements.txt` 只保留到根
`pyproject.toml` 的安装入口；OSGB 的 C++/CMake 依赖仍由 `osgb_pipeline` 单独管理。

核心主链按 V2.3 固定为“空间分块/索引 → 局部 KDTree → 多尺度 PCA 法向稳定性 → 动态区域生长 → RANSAC/TLS → 块内投影足迹合并 → 跨块投影多边形完整链接合并 → 层次化二次合并 → 联合足迹质量重算 → 全局候选复判”。完整点云的独立瓦片识别阶段使用可配置线程池并行；当前普通 LAS 的整体模式是 `2d_xy_fallback`；高分辨率 Mesh/影像缺失时，迹线和张开度只输出不可用状态。

三 ROI 消融实验使用：

```bash
python3 main.py roi-compare \
  --input outputs/root_full_xyz_10/cloud.las \
  --output outputs/roi_compare_v23 --force
```

结果文件为 `outputs/roi_compare_v23/roi_comparison.csv` 和 `roi_comparison.json`。
